Linux系统编程

概述

Linux系统提供了一套完整的系统编程API，涵盖了文件操作、进程管理、设备控制、内存管理和进程间通信等核心功能。这些系统调用提供了对操作系统底层资源的直接访问，是所有高级应用和库函数的基础。

文件描述符 (File Descriptor)

文件描述符是一个非负整数，用于标识打开的文件、管道、套接字等I/O资源。每个进程默认有三个标准文件描述符：

  • 0 - 标准输入 (STDIN_FILENO)
  • 1 - 标准输出 (STDOUT_FILENO)
  • 2 - 标准错误 (STDERR_FILENO)

重要说明

  1. 访问模式必须指定：O_RDONLY、O_WRONLY、O_RDWR这三个访问模式标志必须包含其一，且它们之间互斥，不能同时使用。

重要说明：文件空洞 (File Hole)

lseek() 允许将文件偏移量设置到文件末尾之外（但这不会改变文件的实际大小）。如果之后在这个位置写入数据，那么在间隙（称为”文件空洞”）中读取数据时会返回空字节（\0），直到实际数据被写入到这个间隙中。

文件空洞的特点：

  1. 不占用存储空间：文件空洞不占用实际的磁盘存储空间
  2. 读取时返回零字节：读取空洞区域会返回 \0 字节
  3. 文件大小可能大于实际存储：stat显示的文件大小可能包含空洞部分
  4. 稀疏文件：这种含有空洞的文件称为稀疏文件（sparse file）

access - 检查文件访问权限

参数说明

  • pathname: 要检查的文件路径
  • mode: 检查的访问模式

访问模式

重要说明

权限检查的特殊性：access()函数的权限检查机制与其他系统调用不同：access()使用调用进程的真实UID和GID进行检查，而不是像open()等函数那样使用有效ID。

权限检查的实际含义

access()并不回答”我能否读/写/执行这个文件？”的问题，而是回答一个稍微不同的问题：

“调用我的用户能否读/写/执行这个文件？”

与open()的权限检查区别

返回值

getcwd - 获取当前工作目录

参数说明

  • buf: 存储路径的缓冲区
  • size: 缓区大小

返回值

  • 成功：返回指向buf的指针
  • 失败：返回NULL，设置errno

使用注意事项

  • buf必须足够大以存储完整路径
  • 路径长度可能受系统限制（PATH_MAX）

重要说明

glibc扩展：作为POSIX.1-2001标准的扩展，glibc的getcwd()函数支持动态分配缓冲区：

  • buf为NULL时：如果buf参数为NULL，glibc会使用malloc()动态分配缓冲区
  • 自动确定大小：分配的缓冲区大小会根据实际路径长度确定，除非指定了size参数
  • 内存管理：当使用动态分配时，调用者必须使用free()释放返回的缓冲区
  • size为零：如果size为零，缓冲区会分配为所需的大小

opendir - 打开目录流

参数说明

  • name: 要打开的目录路径名（opendir）
  • fd: 已打开的目录文件描述符（fdopendir）

返回值

  • 成功：返回指向目录流的指针
  • 失败：返回NULL，设置errno

功能说明

opendir()函数打开一个目录流，该目录流可用于后续的目录读取操作。目录流是一个有序的序列，包含目录中的所有目录项。

与open()的区别

  • opendir()专门用于读取目录内容，返回DIR *指针
  • open()用于文件I/O操作，返回文件描述符
  • 目录流有内部状态，会记住当前位置
  • 文件描述符需要手动管理位置

fdopendir的特殊性

fdopendir() 函数接受一个已经打开的目录文件描述符，并将其转换为目录流：

重要注意事项：

  • 文件描述符所有权转移：当 fdopendir() 成功时，文件描述符的所有权转移给目录流
  • 不要手动关闭：调用者不应该手动关闭传入的文件描述符，closedir() 会自动处理
  • 重复关闭危险：如果在调用 closedir() 后再手动关闭文件描述符，会导致未定义行为

closedir - 关闭目录流

参数说明

  • dirp: 要关闭的目录流指针

返回值

  • 成功：返回0
  • 失败：返回-1，设置errno

功能说明

closedir()函数关闭目录流并释放相关资源。调用此函数后，dirp指针变为无效，不能再用于目录操作。

重要说明

1. 资源管理

  • 必须为每个成功打开的目录流调用closedir()
  • 忘记关闭目录流会导致文件描述符泄漏

2. 底层文件描述符

  • 目录流内部包含一个文件描述符
  • closedir()会自动关闭这个文件描述符

dup / dup2 - 复制文件描述符

功能

  • dup: 复制文件描述符，返回新的最小可用文件描述符
  • dup2: 复制文件描述符到指定的文件描述符

参数说明

  • oldfd: 要复制的原始文件描述符
  • newfd: 目标文件描述符（仅用于dup2）

返回值

  • 成功：dup返回新的文件描述符，dup2返回newfd
  • 失败：返回-1，设置errno

重要说明：文件描述符复制的底层机制

共享打开文件描述

复制后的文件描述符与原始文件描述符可以互换使用，因为它们指向同一个打开文件描述（open file description）：

共享的内容：

  • 文件偏移量：两个描述符共享相同的文件读写位置
  • 文件状态标志：如O_APPEND、O_NONBLOCK等

不共享文件描述符标志

两个文件描述符不共享文件描述符级别的标志，最重要的是close-on-exec标志（FD_CLOEXEC）：

  • close-on-exec标志默认关闭：复制的新描述符的FD_CLOEXEC标志默认为关闭状态
  • 这意味着在exec系列函数执行新程序时，这个描述符不会被自动关闭

原子性操作

dup2()提供了原子性保证：

  • 如果newfd已经打开，dup2()会先关闭它
  • 这个操作是原子的，不会被信号中断
